# 大型书稿分规模策略（M1 / M2 / M3）

**版本**：1.59D · **权威流程**：[`section-3-workflow.md`](../01-core/section-3-workflow.md) 大型项目段落

## 阈值（与 §3 一致）

| 等级 | 规模（约） | 核心应对 |
|------|------------|----------|
| **M1** | 20–50 万字 / 15–35 章 | 主题漂移监控、目录冻结流程 |
| **M2** | 50–100 万字 / 35–70 章 | 上下文溢出、分卷/索引、`chapter-scan-result.json` |
| **M3** | ≥100 万字 / ≥70 章 | 结构碎片化、Auto-Run 停机报告（见 §3 引用） |

## P0

预计 ≥20 万字或 ≥15 章时，**必须先加载**本策略对应等级条款再继续 S3，禁止仅口头宣告等级。

## M3 专项质检约束（P0 强制，v2.0.0 新增）

> **来源**：2026-04-02 杜氏知识集质检复盘（50章 M3 项目）——批量写作完成后未执行质检，台账虚报字数 4 倍，大量骨架稿被标记为"已完成"，S6 报告声称"166万字完结"而实际仅 35~40 万字。  
> **根因**：M3 规模策略缺乏写作完成后的强制质检钩子；规模越大，骨架稿累积风险越高，但质检约束反而更弱。

### §M3-QC-1 批量写作后强制质检扫描（P0）

```
M3 项目（≥70章 / ≥100万字）批量写作结束后，
在进入 S4（合稿）/ S5（终审）/ S6（完结）之前，
必须先执行全书质检扫描（§3.7 全书质检 SOP）：

触发条件（任一满足）：
  - 用户说"全书写完了" / "开始终审" / "生成S6报告"
  - 模型宣告"完成全书 S3 章节写作"
  - 累计写作章节数达到目录计划章节总数

强制执行步骤（不可跳过）：
  Step 1：磁盘扫描 — 列出所有章节文件 + 统计字符数
  Step 2：对比台账 — 核验台账状态与磁盘实测的一致性
  Step 3：骨架稿清点 — 统计字符数 < 目标×60% 的章节列表
  Step 4：输出扫描摘要（格式见下）

M3 质检扫描摘要输出格式：

━━━━━━ M3 全书质检扫描摘要 ━━━━━━
扫描章节总数：{M}章
已扫描：{M}章 / 磁盘字符数合计：{N}字符
达标章节（≥60%目标）：{A}章（{A/M×100}%）
骨架稿章节（<60%目标）：{B}章（{B/M×100}%）
台账与磁盘不一致：{C}章

如有骨架稿章节，须列出：
  Ch{NN}·{标题} | 磁盘{N}字 | 目标{M}字 | {N/M×100}%
  ...（列出所有骨架稿）

⚠️ 须修正台账后方可进入 S4/S5/S6。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**禁止行为**：
```
❌ M3 项目宣告"全书写作完成"但未执行磁盘扫描
❌ 在骨架稿章节存在的情况下，S6 报告声称"全书 N 万字完结"
❌ 以"连续写作模式/快速推进授权"为由跳过 M3 强制质检扫描
```

### §M3-QC-2 骨架稿分级标注全流程传播（P0）

> **问题**：骨架稿标注 `⚠️ 骨架稿·待扩写` 仅在章节文件头部，未传播到 S5 终审报告和 S6 完结报告的完成度声明中，用户看到 S6 报告时无法感知骨架稿的存在。

```
骨架稿标注传播规则（P0 强制）：

1. 章节文件层（已有，§3.3.2）：
   章节正文头部标注 ⚠️ 骨架稿·待扩写

2. 台账层（v2.0.0 强化）：
   chapter-status.md 对应行状态必须为 ⚠️ 骨架稿（不得标为 ✅ 已完成）
   字段必须为磁盘实测字符数（§3.3.4）

3. S5 终审报告层（v2.0.0 新增）：
   骨架稿章节须在 S5 报告中单独列出（§3.5 §3.5.1）
   不得对含骨架稿的书籍输出"出版级终稿"声明

4. S6 完结报告层（v2.0.0 强化）：
   骨架稿章节须在 §3.6 四级完成度声明中归入 ⚠️ 骨架完成（待扩写）
   全书完成度百分比须以"完整达标/骨架/未完成"三级声明（不可合并为单一数字）
```

### §M3-QC-3 M3 项目阶段质检节点（P1 建议）

> 对于超长项目（≥100万字/≥70章），建议在写作过程中设置阶段性质检节点，而非等到全书写完后才发现骨架稿积累。

```
M3 项目阶段质检建议（P1）：

  每完成 20% 进度时（如70章项目每完成14章）：
  执行一次轻量质检扫描：
    - 列出本批次章节字符数
    - 标注骨架稿（若有）
    - 更新台账
    - 输出进度摘要（本阶段达标率 + 骨架稿清单）
    
  好处：
  - 及早发现质量梯度塌陷（批量写作后期章节质量下降）
  - 给用户选择：继续写还是先扩写骨架稿
  - 避免全书写完后骨架稿过多导致大规模返工
```
