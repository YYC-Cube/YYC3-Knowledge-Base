## §1 四层检查单 + 评分公式

> **计分体系（与 [`metrics.md`](./metrics.md) §1 一致，已消除旧版「满分10却分项加总>10」矛盾）**  
> - **原始分**满分 **20** = S(6) + P(4) + C(4) + B(5) + V1(1)。  
> - **折算分** = 原始分 ÷ 2，满分 **10**（可同时汇报「原始/20」与「折算/10」）。  
> - **通过**：折算分 **≥ 7.5** ⇔ 原始分 **≥ 15**。  
> - **边界带**：折算分 **≥ 7.0 且 < 7.5**（原始分约 **14–<15**）→ **建议修订**后重审；**< 7.0** → 打回（与 SKILL §0 置信度阈值一致）。  
> - **Bonus**：可选加分，**不计入**上述 20 分满额；须在报告中单列。  
> - **G 层**：合规与阻断，**不计入** 20 分；见 §G。  
>
> **各层原始分**：S 层 6 条（S1–S6）各 1 分；P/C 各 4 条各 1 分；**B 层 5 个维度**（B1、B2-A、B2-B、B2-C、B3）**各 1 分**——下表中 B2-A、B2-C、B3 下的多行阈值为**同一维度**的细则，**不重复计分**。V1 达标 1 分。

### §1.0 改稿后防反弹（S 层再扫）

> **术语**：下表 **S 层「S4」** = **连接词密度**（质量维度）；**工作流阶段 S4** = **排版构建**（`build.mjs`）。二者**不同域**，切勿混谈「S4 过了」却未跑构建。

> **审计缺口补齐**：大段改写、去 AI 味或用户粘贴替换后，须**重新跑**与 S 层相关的自动项（至少 S2 程度副词、S4 连接词、S5 buzzword、S6 标点），避免「改前通过、改后未检」。  
> **留痕**：并行写作或主编验收时，建议 Writer 交稿附带 [`quality-AI-scan.md`](./quality-AI-scan.md) 已填表，便于对照 S6 破折号等「规则有、扫描易漏」项。  
> **执行**：宿主在 Writer 提交新版本后触发 Critic-S 或等价任务；若仅改局部，可对变更段做增量扫描，但**不得**默认整章免检。

### §1.0.1 Writer 与 S6 强制闭环（去标点味）

- **Critic 报 S6 未达标**（破折号/分号/感叹号等任一项越阈）：**Writer 须做句式级重写**并**重新跑 S6** 直至达标，或取得**用户书面接受风险**；**禁止**仅以替换标点敷衍导致语义受损。  
- **单章 S6 通过**不能替代**全书**破折号总账：汇编后须执行 **C0-1**，见下表与 [`book-level-consistency.md`](./book-level-consistency.md)。

### §1.0.2 S2·A 类词计分加码

> 不改变「S2 档原始分 0/1」的布尔结构；用于**报告与主编裁量**，防止「显著」「非常」偶发漏网。

- **规则**：质量报告中单列 **A 类命中次数**；在**折算分**汇报时，可在主编确认后按 **每处 −0.5** 分累加惩罚，**上限 −3**（与 `quality-S.md` A 类表一致）。  
- **工具**：`quality-auditor.mjs` 合并报告输出 **A 类词**命中次数。

#### 多路并行写作时的 G4 默认策略（P0，审计对齐）

- **G4（数据来源标注）视为默认启用**：主编 / team-lead 须在团队任务中写明遵守 [`citation-format.md`](./citation-format.md)；各章须有 **本章数据来源索引**（或等价结构），并与检索门禁一致。

- **单会话单 Agent 逐章串行**时，G 层默认策略不变（仍以用户启用合规检查为准）。

#### G6 虚拟读者挑战（每章成文后，P1 建议）

> **来源**：人类写作质量模式 QM-7（读者视角验证）——出版编辑在终稿前常邀请「目标读者测读者」，在章节完成后注入目标读者视角的挑战性问题，及早发现内容盲区。  
> **执行时机**：每章章内自审卡填写时（见 `section-3-workflow.md §「章节任务卡（Chapter Brief）」`）。

| # | 检查项 | 触发条件 | 处置 |
|---|--------|----------|------|
| G6-1 | 目标读者能否在读完本章后立即获得可操作的认知/方法？ | 每章成文后 | 「否」时在自审卡记录改进建议，不强制阻断 |
| G6-2 | 本章是否预设了读者已知但实际未必知道的背景知识？ | 每章成文后 | 「是」时在章节适当位置补充前置知识或参考引导 |
| G6-3 | 目标读者最可能提出的「为什么这样说？」能否在本章找到答案？ | 章末检查 | 找不到答案时，须在章末或数据来源索引中给出参考依据 |

**执行形式**（写入章内自审卡）：

```
虚拟读者挑战：
Q1：{目标读者最可能问的核心问题} → 本章回应：{充分/部分/未回应（需改进）}
Q2：{目标读者的第二个挑战性问题} → 本章回应：{充分/部分/未回应（需改进）}
```

**注意**：G6 为 **P1 建议**，不阻断门禁；但「未回应（需改进）」项须写入「改进建议」字段，作为下次修订的输入。

#### G7 核心主张跨阶段追踪（S0–S6 全流程，P1）

> **来源**：人类写作质量模式 QM-1（选题锁定）——职业作者在每章动笔前都会将「核心主张」贴在显眼处，防止章节论述与全书宗旨脱节。  
> **配套代码**：`BookWorkflowOrchestrator.setCoreThesis()` + `checkCoreThesisAlignment()`。

| 阶段 | 核心主张追踪要求 |
|------|---------------|
| **S1** | 脉络确认稿中须有「一句话核心主张」字段（≤25字）；用户确认后锁定 |
| **S3 每章** | Chapter Brief 中「核心主张对齐」须填写本章与全书主张的关系（支撑/展开/对比/验证）；章内自审卡含「核心主张对齐」检查项 |
| **S5 终审** | 终稿质量报告须包含「全书核心主张一致性确认」：抽查 5 章以上，核实各章论述均可追溯至全书核心主张 |
| **S6 完结** | 完结回顾须含「核心主张落地情况」：全书最终的交付物是否有力支撑了 S1 确定的一句话核心主张 |

**追踪模板**（写入 `[S1] 脉络确认稿` 并在后续阶段引用）：

```
全书核心主张（P0 锁定）：{≤25字，用户确认后不得擅自更改}
确认时间：{S1 确认时间}

各章对齐状态（S5 终审时填写）：
| 章编号 | 章节标题 | 与主张的关系 | 对齐评分（高/中/低）|
|--------|---------|------------|-------------------|
| …      | …       | …          | …                 |
```

#### G层评分规则

- G层为**可选项**，不计入 S/P/C/B/V1 的 **20 分原始分**（及折算后的 10 分制）
- G层通过条件：G3无阻断 + 其他项无高危提示
- 启用学术模式时：G1强触发项必须完成确认才可继续
- 启用商用模式时：G5-1/G5-3高危提示必须解决才可发布

#### G8 模型知识兜底协议（素材不足时的合规使用规范，P1）

> **问题**：素材库不足时，模型倾向于用内置知识填充正文而不声明，读者无从判断内容是否经过外部核实。  
> **原则**：在用户明确同意的前提下，允许使用模型知识补充，但**必须透明标注**，绝不允许静默混入已核实内容中。

| # | 规则 | 阈值 / 触发条件 | 处置 |
|---|------|---------------|------|
| G8-1 | 使用模型知识前须用户显式同意 | 素材缺口出现 / Brief 中标注「模型知识兜底」 | 禁止在未经用户同意时使用；可向用户说「本节有 X 个支撑点需要素材，您是否授权使用模型知识暂代并标注？」|
| G8-2 | 每个模型知识段落末尾须附标注 | 使用模型知识写入正文 | 段末加 `〔模型知识，未经外部检索核实〕` |
| G8-3 | 章末素材来源索引须注明模型知识条数 | 章末检查 | 在「本章数据来源索引」中单列「模型知识（未核实）：{N}处」 |
| G8-4 | S5 终审时须汇总全书模型知识占比 | S5 终稿审查 | 终稿质量报告须含「模型知识段落占比」字段；占比 >20% 时须向用户提示建议补检 |
| G8-5 | 高风险事实类内容禁止使用模型知识 | 涉及具体数字/年份/人名/地名/法规条文 | 此类内容即使用户同意，也须明确标注「待核实」，不得以模型知识作为「已确认事实」写入 |

> **用户启用话术**：「可以用你的知识补充，但需标注」/ 「素材不足的部分用模型知识填充并标记」  
> **配套字段**：`search-policy.json → materialLibrary.modelKnowledgeTag` 和 `modelKnowledgeProtocol`

### G1 违规词汇检测实现

**学术场景检测**（学术模式启用）：

```
检测方式：关键词库匹配（keywords.md）

  - 强触发（弹窗+强制确认）：论文/毕业/期刊/署名/实验数据/诚信类
```

```
检测方式：基础词库匹配

  - 政治敏感词（发现即G3人工复核）

  - 色情低俗词
  - 违法犯罪词
```

**过度绝对化检测**：
```
检测位置：全书正文
检测方式：绝对词表匹配
```

### G2 引用格式检测实现

**无来源表述检测**：

```
  - "据显示" → 必须改为"[XXX](来源)显示"或删除
```

## §QC-PROCESS 质检流程执行规范（v2.0.0 新增）

> **来源**：2026-04-02 杜氏知识集全面质检复盘——发现质检流程本身缺乏标准化约束，导致"已质检"声明与实际执行内容严重脱节。本节建立质检过程的 P0 约束，是对 §3 报告模板的过程侧补充。

### §QC-1 质检过程 P0 约束（禁令 F/G/H）

| 禁令 | 描述 | 条文 |
|------|------|------|
| **禁令 F** | 禁止零磁盘扫描的质检声明 | §3.7.1（section-3-workflow.md） |
| **禁令 G** | S5 抽样率须量化，≥20%章节实际读取并记录字符数 | §3.5.1（section-3-workflow.md） |
| **禁令 H** | 台账字数字段须源自磁盘读取，禁止自报估算 | §3.3.4（section-3-workflow.md） |

**触发方式**：用户说"质检"/"全面质检"/"检查全书"/"S5终审"时，自动激活本节约束。

### §QC-2 质检自检单（执行前必填）

> **目的**：防止"形式性质检"——模型在未实际读取文件的情况下输出看似合规的质检报告。

```
━━━━━━ 📋 质检执行自检单 ━━━━━━

执行前确认（禁止跳过）：
  [ ] 已列出全部章节文件清单（list_dir/Glob）
  [ ] 已统计每章磁盘字符数（非估算，来自 read_file 或 PowerShell）
  [ ] 抽查计划已输出（章节列表 + 覆盖率声明）
  [ ] 抽查覆盖每编至少 1 章

执行中确认：
  [ ] 每章抽查均执行 read_file（非凭记忆）
  [ ] 跨章重叠检测已执行（CX-4 + 人物重叠）
  [ ] 台账 vs 磁盘对比已执行

执行后确认：
  [ ] 质检报告已写入磁盘（§3.7.3 模板）
  [ ] 台账已按磁盘实测修正（§3.7.4）
  [ ] 报告写入后已执行 read_file 验证（§3.X.1）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**禁止行为**：

```
❌ 未执行 list_dir/Glob 扫描而声明"已扫描全部章节"
❌ 未执行 read_file 而声明"已抽查 N 章"
❌ 在台账字数为估算值的情况下声明"字数统计已完成"
❌ 在未读取任何章节的情况下输出"综合评分 X/10"
❌ 将 S5 终审报告与全书质检报告混为一谈（两者功能不同）
```

### §QC-3 质检报告与 S5 终审报告的区别

| 维度 | 全书质检报告（§3.7.3） | S5 终审质量报告（§3） |
|------|---------------------|-------------------|
| **核心问题** | "书写完成了吗？台账是否真实？" | "已写章节质量是否达到发布标准？" |
| **评分体系** | 台账准确率 × 内容达标率 × CX一致性 | S/P/C/B/V1 二十分体系 |
| **主要产出** | 磁盘扫描表 + 骨架稿清单 + 建议 | S/P/C/B 逐章评分 + 数据保鲜表 |
| **执行时机** | 任意时刻（用户要求时）/ S5 之前 | S5 阶段（全书写作完成后） |
| **互替性** | **不可互替**，两者互补 | 同左 |

> **工作流建议**：全书质检（§3.7.2）宜在 S5 终审之前执行，作为"进入 S5 的前置条件检查"，确保台账状态真实后再做章节级质量评分。
