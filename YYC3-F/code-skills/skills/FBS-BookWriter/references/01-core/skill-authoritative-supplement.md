## §0 总纲

### 平台适配

本 SKILL 运行于支持 **Skills** 的宿主（如 **CodeBuddy Code**、**WorkBuddy**），利用以下能力（以实际宿主开放工具为准）：
- **联网搜索（核心知识基础）**：所有策略的知识来源
- **并行Task调度（高级可选）**：多成员并行写书场景；推荐使用单智能体串行模式（分块推送+章内自审），token 更低、无并发限流
- **图像与视觉（分层，见 `visual.md`）**：L1 位图（`coverImage` 或宿主生成后落盘）；L2/L3 SVG；L4 图标/占位
- **文件系统写入**：直接创建项目结构和保存产出物
- **流式输出**：渐进式推送，结果即到即推

**产出物验收（与宿主 UI 解耦）**：若 WorkBuddy 等仅在界面展示 **「生成失败 unknown」** 而 **未**向 Skill 传入可解析错误，模型**不得**默认「未生成」。应 **Read 本书根** 下 §3.X 约定之 **`[S0]`–`[S6]`** `.md`，或运行 **`node scripts/verify-expected-artifacts.mjs --book-root <本书根>`** 做清单核对；详见主文件 **「宿主误报失败与磁盘真值」**。

在 **WorkBuddy** 中，Skill 是任务与工作台里的**一种能力、一类长文档场景**；用户从 [官方文档](https://www.codebuddy.cn/docs/workbuddy/Overview) 所描述的「创建任务—对话—结果验收」路径进入，本 Skill 负责在会话内落实 S0–S6 与质量门禁。**用好 WorkBuddy 是用好福帮手 Skill 的底座**；全局心智对齐见 [workbuddy-skill-foundation.md](../05-ops/workbuddy-skill-foundation.md)（助手与朋友式执行姿态同 §1 渐进式输出、触发词首响）。

| 触点 | 规则 | 示例 |

**助手在执行时的核心原则**：

- **先摘要后展开**：每个长步骤先给你关键结论，再展开细节，不一次性塞一大堆。
- **不能凭记忆写事实**：凡是涉及数据、年份、政策、产品情况的内容，必须先联网查证再落笔，不查就不能声称「已核实」。
- **工具出问题要说**：联网检索或其他工具超时了，会告诉你现在在哪个步骤、可以怎么重试，不会悄悄卡住。
- **开始写稿时先说一声**：大纲确认后进入写稿，第一句话会告诉你「现在开始逐章写了，先搜一轮本章资料」。
- **写稿过程每隔15秒说一句进展**：不会长时间没动静，每完成一小节就推送，你看到内容出来就是在正常运行。
- **平台限流时会说**：遇到请求太多被平台限制，会告诉你「稍等10秒，串行重试」，不会静默卡死。

**联网核实的具体规则（P0，不能绕过）**：

① **先查今天的日期**：调研开始时第一件事就是联网查当天日期，写进调研简报「时间基准」行，整个项目以此为准，不用模型自己推断。

② **写年份之前先查**：正文里出现具体年份（如「2024年某事件」）或「最新/当前/近年来」这类说法，必须先查到来源再写进去。没有来源就标注「（待核实年份）」，不能假装查过了。搜索时不要在关键词里加具体年份（比如「AI应用 2024」），要用「AI应用 最新」这样的说法。

③ **拿不准的事情自动去查**：写的时候如果对某个事实心里没底（比如脑子里浮现「可能/大约/据说/估计」这类措辞），暂停写入，先去搜一下；搜不到就标注「（数据待核实）」，不能悄悄写进去当成定论。

④ **引用规范条文先核实**：说「根据某文件某条款」之类的话，必须先把那个文件打开、确认条文确实存在再说；找不到就说「我找不到这个表述，让我核实后再回答」，不能凭记忆编。

**大型项目和特殊情况**：

- **20万字以上的项目**：大纲确认后立刻告诉你这是几级规模（小/中/大），启用对应的保障机制（比如主题漂移监控、跨会话恢复）。新开一个会话时不能不读之前的文件就直接开写。
- **生成 HTML 终稿**：需要本地跑构建脚本（`node …/assets/build.mjs`），不能用对话里手写的临时脚本来替代。
- **声称「HTML完成可发布」之前**：要先跑烟测验收，验收没过不能在报告里写「HTML已达标」。没有 Node 环境时要说清楚只能交付 Markdown 版本。

### 合规红线

以下场景为 **高风险区**，必须触发合规机制：
1. **学术用途**：论文/毕业/期刊/学位申请等 → 触发学术合规警告
2. **AI生成内容**：自动附加AI辅助声明
3. **版权风险**：引用需标注来源，数据需联网校验
4. **G3 敏感内容**（政治/色情暴力/违法犯罪/严重谣言等，见 `quality-check.md`）→ **阻断**继续生成或发布该段；须提示用户修改后重试，**禁止静默继续**（与 G3 实现条款一致）
5. **G5 版权与商用素材**（用户启用**商用模式**时）：第三方图片/长引用/特殊字体等须满足声明与授权要求，详见 [`quality-check.md`](../02-quality/quality-check.md) **G5**；未解决高危项前**不宜对外发布**

### 三条铁律

1. **人定方向，AI展开，人确认，AI执行。** 未经确认不落稿。
2. **去AI味是硬性标准。** 读起来像AI写的=不合格。五层规则：`quality-S.md`（S层6条）+ `quality-PLC.md`（**P层4条 + C层5条（C1–C4 计入原始分4分，C5 衔接为建议项不计分）+ B层篇级**，其中 **B0** 为标题编号唯一性，**B1–B3** 及 **B2 子项**见 §B）。**权威规范源（canonical）**：[quality-S.md](../02-quality/quality-S.md) 与 [quality-PLC.md](../02-quality/quality-PLC.md)（若仓库根级存在同名镜像，以 `02-quality/` 为准）。**去AI味规则的知识来源：联网搜索优秀作品，分析写作技巧，提取表达方式，迭代优化规则。**
3. **中文排版遵循中文标准。** 全段2em缩进、标题左对齐、金句不居中。详见 `typography.md`。**排版标准的知识来源：联网搜索最新中文排版规范，跟踪国家标准更新，迭代优化排版规则。**

### 第四条铁律（P0）：主题一致性

**上下文跳变是严重故障。** 从 S0 到 S6，主题必须始终保持一致。任何阶段切换、文件读取、多智能体并行，都必须携带主题校验。

- **S0 锁定**：完成调研后显式锁定主题，写入简报首行  
- **阶段校验**：S1→S2→S3… 每次切换校验主题一致性  
- **文件校验**：读取历史文件前校验文件主题与当前主题一致  
- **用户确认**：用户说「确认」时必须回显当前主题  

详见 [topic-consistency-gate.md](../05-ops/topic-consistency-gate.md) 与 [book-level-consistency.md](../02-quality/book-level-consistency.md) **C0-4**。

### 交付格式策略

**核心原则**：**MD** 为唯一「零环境」真理源；**专业 HTML（D1）** 依赖本地 `assets/build.mjs`；PDF/DOCX 为可选链。三档定义见 [`html-deliverable-gate.md`](../05-ops/html-deliverable-gate.md)。

| 格式 | 定位 | 可靠性 | 说明 |
|------|------|--------|------|
| **MD** | 主力文字输出 | 100% | 跨平台兼容，任何编辑器可打开 |
| **HTML（D1）** | 规范可视化终稿 | Node 18+、`npm install`（**含** `markdown-it-footnote`，见随包 `package.json`） | **须**经 `assets/build.mjs`；含目录/版权/脚注/Mermaid 管线；**禁止**用正则子集冒充；无 Node 时改 **D2** |
| **HTML（D3）** | 会话预览草稿 | 不保证 | 仅内部预览，须在页面或对话中标注；**不得**写入 S6「可对外发布」 |
| **PDF** | 用户自助转换 | 依赖工具链 | 自 D1 HTML 打印或 `build.mjs` 输出 |
| **DOCX** | 用户自助转换 | 依赖工具链 | `html-to-docx` / 在线工具，见 `delivery.md` |

**详细说明**：
- MD：可单文件或多文件；全书元数据（字数等）须与磁盘或可复现统计一致，禁止虚报数量级。
- HTML：**终稿**默认指 D1；**S6 前**运行 `node …/scripts/html-delivery-smoke.mjs --html <文件> --strict --fail-on-warn`（与 `html-deliverable-gate.md` 一致）。
- PDF/DOCX：见 `build.md`；不内置弱中文依赖的默认打包。

**一键导出四选项**：详见 [`delivery.md`](../05-ops/delivery.md)

### 联网搜索规范（强制动作）

> **核心原则**：凡事实型、数据型、政策与竞品型内容，**必须先检索再落稿**；联网检索是质量门禁，不是可选增强。阶段清单见 `references/01-core/section-3-workflow.md` §3.0.5 与 [`references/05-ops/search-policy.json`](../05-ops/search-policy.json)。

**搜索时机（均为强制，除非用户明确声明纯虚构创作并承担风险）**：
- **S0–S2.5**：定位、目录、脉络各阶段按工作流执行检索
- **S3 每一章**：成文前 **至少 2 次**主题相关检索（默认；次数以 `search-policy.json` 中 `chapterWriting.minQueriesPerChapter` 为准，宿主应记录以便审计）
- **S5 终审阶段**：对**拟发布**的事实主张、统计数据、法规与引用进行**按需检索或复核**（`search-policy.json` 的 `mandatoryWebSearchStages` 已含 **S5**；详见同文件 `s5FinalReviewNotes`）；**禁止**仅凭早期会话记忆定稿敏感事实句
- **主动搜索**：涉及数据/工具/政策/史实/行业报告 → 先搜再写
- **验证搜索**：写作中发现冲突/模糊 → 立即搜索验证
- **优化搜索**：质量评分 &lt;7 或用户反馈负面 → 检索改进范例与标准表述

**搜索质量标准**：
- **数据新鲜度**：优先搜索1年内的数据（2025-2026年）
- **来源权威性**：优先官方机构/头部机构/知名专家
- **交叉验证**：至少2个独立来源确认同一事实
- **引用标注**：所有数据/史实/专家观点必须标注来源
- **检索落地**：检索记录中的结论须体现在**正文句旁、脚注或「本章数据来源索引」**；禁止仅堆砌「检索执行记录」而正文仍写无来源分省/精确数（见 `search-policy.json` → `chapterWriting.notes`）

### 执行规则

| 规则 | 说明 |
|------|------|
| 指正即执行 | 用户纠正→直接改，不反问 |
| 共识用原话 | 保留用户原始表述 |
| 产出即解耦 | 文档独立成文，禁止"如前所述" |
| 联网优先 | 涉及数据/工具/政策→先搜再写；**禁止**无检索凭模型记忆写事实句 |

### 背书与声明（质量相关位置）

仅在 **AI 辅助声明**、**数据保鲜表** 等质量背书区出现工具/校验说明，不做正文流中的商业水印：

| 位置 | 形式 |
|------|------|
| AI 辅助声明 | 说明使用 AI 辅助的范围；最终文责由作者承担 |
| 数据保鲜表 | 每行可标注「来源已核对 ✓」等中性表述 |

禁止在正文、金句、章首等阅读流中插入商业品牌或未经确认的署名。

### 心跳与阶段播报协议

> **详细协议**：见 [heartbeat-protocol.md](../05-ops/heartbeat-protocol.md)

**执行摘要（入主规范，与 §6.5.1 一致）**：
- 单次操作预计 **≥30s** 时，每 **15s** 输出一行用户可读心跳（静默心跳），避免误判卡死。
- **页级/单次拉取**默认超时见 `search-policy.json` → `searchAccessPolicy.singlePageTimeoutMs`（默认 **15000ms**）；**整段检索任务**仍可沿用 **30–60s** 级链路预算与退避重试。仍失败须说明阶段与可重试项，**禁止**用模型记忆编造事实句顶替。
- 多成员并行时：若子任务**连续 2 个**心跳周期（默认 **60s/次**，见 `section-6-tech.md` §6.4）无响应，宿主应暂停派发、播报并允许降级串行。
- 写盘失败：**最多 3 次**重试（间隔约 5s）；仍失败则把全文输出到会话并提示手动保存。

### 持续追踪

- **热点追踪** — 自动监控热点动态，定时推送新角度
- **系列产出** — 同一话题不同角度持续输出
- **内容日历** — 智能调度最佳发布时间

### 品牌植入规则

- 自然融入，禁止硬广
- 价值前置，案例引出
- 多角度切入，避免重复
