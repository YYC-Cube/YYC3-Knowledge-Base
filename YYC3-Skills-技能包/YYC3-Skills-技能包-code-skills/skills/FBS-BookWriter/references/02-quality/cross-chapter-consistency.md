# 跨章一致性（全书层 **CX** · 手册）

> **定位**：弥补 S/P/C/B 以**单章**为主、**不覆盖章间逻辑**的缺口。**不计入** S/P/C/B 二十分；与 **C0** 并列，在 **多路并行合稿后、S5 终审前** 执行。  
> **术语**：本书 **CX** = 全书跨章层；**勿与** `quality-PLC.md` §**C1**（章内「表态」条款）混淆（测试报告 05）。  
> **版本**：1.59D（CX-4 强制化 + 分类型章节写作前强制重叠检测门禁）

---

## 1. 何时必须做 CX

| 场景 | 是否执行 CX |
|------|----------------|
| 单会话单 Agent 逐章串行，且后章写作时可见前章定稿 | 可选（仍建议 S5 前抽检） |
| **≥2 名 Writer 并行写不同章节** | **必须** |
| 对称结构章节（如产品 A vs 产品 B 深度剖析） | **必须**（含对称性检视） |
| **分类型章节（名人传/人物志/省域/分类型体裁）** | **必须（v2.0.0 升级为 P0）** |

---

## 2. 检查项（CX-1 — CX-7）

主编或 **全书审校角色（Book Auditor）** 按下列维度出一份《全书一致性审查报告》（Markdown 即可）。

| 编号 | 内容 | 通过标准（建议） | 优先级 |
|------|------|-------------------|----|
| **CX-1** | 同一主题在不同章的**论断**是否矛盾（含推测 vs 已证实混用） | 列出矛盾点 = 0 或已标注「估算/待核实」 | P1 |
| **CX-2** | **同一数据点**多章出现时数值、单位、口径是否一致 | 不一致 = 0 或已在附录说明口径 | P1 |
| **CX-3** | **对称章节**小节结构、深度是否大体对等（避免一详一略造成偏见） | 显著不对称须说明或改稿 | P1 |
| **CX-4** | **重复论述**：核心段落是否在多章完整复述 / **人物/地区在分类型体裁下的跨章重叠** | 后续章改为引用前文或压缩复述；分类型章节见 §CX-4-E | **P0（v2.0.0 升级）** |
| **CX-5** | 前文提出的**分析框架**（如对比表、瓶颈清单）后文是否呼应 | 无头无尾 = 0 | P1 |
| **CX-6** | 同一来源在不同章引用时**口径**一致 | 冲突须统一 | P1 |
| **CX-7** | **风格一致性**：全书**叙事声调、人称、例证偏好**是否前后统一 | 声调漂移（如前半正式后半口语）= 须说明或改稿；主动参照 `[S1] 风格档案` 判断 | P1 |

## §CX-4-E 分类型章节人物/地区重叠强制检测（P0，v2.0.0 新增）

> **来源**：2026-04-02 杜氏知识集质检复盘——发现4组跨章人物重叠（杜月笙：Ch36/Ch40；杜甫：Ch37/Ch41；杜牧：Ch38/Ch42；杜预：Ch39/Ch43），且均未在写作前检测，导致同一人物出现两次完整叙述，读者体验割裂，内容价值下降。  
> **原有问题**：CX-4 为 P1 建议级，无写作前强制触发机制，仅在 S5 后期合稿时作为可选项检查，已无法阻止重叠写入。

### 触发条件（分类型章节写作前自动激活）

当 `project-config.json` 中的 `genreTag` 或 `[S2]目录草案.md` 包含以下关键词时，本规则自动升级为 **P0 强制**：

```
分类型章节体裁触发词（任一命中）：
  族谱类：族谱 / 人物志 / 名人录 / 名人传 / 列传 / 人物传 / 名人辑
  地理类：分省 / 分地区 / 分县 / 各地 / 地域分布 / 郡望 / 堂号
  历史分类类：各朝 / 各代 / 各期 / 各时期 / 历朝 / 朝代梳理
  其他分类型：各类 / 各编分类型
```

### 强制执行流程（P0，写作前门禁）

```
分类型章节写作前（Chapter Brief 输出后、正文成文前）：

Step 0：判断本章是否为分类型章节（含上述触发词）
  └─ 否 → 跳过本检测，按常规流程继续
  └─ 是 → 强制执行 Step 1~3

Step 1：读取去重台账
  读取 .fbs/book-context-brief.md 中的「已写人物/地区/事件清单」
  （来自 §3.3.3 的 book-context-brief.md 去重台账）
  
  若台账不存在（首章）→ 输出「首章，无前序重叠风险」→ 跳至 Step 3

Step 2：对比检测
  将本章 Chapter Brief 中预计出现的人物/地区/事件，
  与台账中的已写清单进行对比：
  
  ├─ 无重叠 → 输出「✅ [CX-4-E] 无重叠」→ 跳至 Step 3
  └─ 发现重叠 → 强制输出重叠预警（格式见下）并等待用户选择：
  
  「🔴 [CX-4-E 重叠检测·P0 阻断]
   以下人物/地区/事件已在前序章节完整叙述：
   - {重叠项1}（首见：Ch{NN}·{章节标题}）
   - {重叠项2}（首见：Ch{NN}·{章节标题}）
   
   处理方式（必须选择，不可跳过）：
   A. ★ 本章着重写「新角度/补充信息」，前章内容以「详见第{N}章」引用（推荐）
   B. 简述概要（≤200字）后跳转前章：「如需详情请参阅第{N}章」
   C. 本章需要完整叙述（用户知情接受重复，写入 project-config.json）
   
   请选择 A/B/C（默认 A，30秒后自动采用 A）。」

Step 3：每章写作完成后，更新去重台账
  追加本章新出现的人物/地区/事件到 .fbs/book-context-brief.md：
  | {名称} | Ch{NN} | {≤20字简述} | {ISO} |
  
  此步骤与台账更新（§3.3.1）合并执行，同一执行单元完成。
```

**禁止行为**：

```
❌ 检测到重叠后直接成文，不输出预警、不等待用户选择
❌ 在 Chapter Brief 中已知本章将出现已写人物，但不执行 Step 1~2
❌ 以「用户授权快速推进」为由跳过重叠检测（P0 不受授权豁免）
```

## 3. 与 C0、S5 的顺序

```
多章初稿齐备 → 汇编合并
  → CX（本书跨章逻辑与数据，含 CX-7 风格一致性）
  → CX-4-E（分类型章节人物/地区重叠，P0，写作前触发 + S5前全量核查）
  → C0（本书）术语 / 破折号 / 主题锁
  → S5 终稿流程（quality-check、Proofer、G 层等）
```

### CX-7 风格一致性检查细则

> **来源**：人类写作质量模式 QM-3（风格一致性监测）——出版编辑在合稿阶段的标准检查项，对单智能体串行与多 Writer 并行模式均适用。

| 维度 | 检查要点 | 常见失效模式 |
|------|---------|------------|
| **叙事声调** | 全书是否维持 `[S1] 风格档案` 中选定的语气（严肃/通俗/对话式/学术式）| 前半严肃、后半口语化；同一章内切换语气 |
| **人称一致性** | 全书是否统一使用第二人称「你」或第三人称「读者」（不混用） | 第1章用「你」，后半用「他们」或「读者们」 |
| **例证偏好** | 例证来源类型（本土案例/国际案例/数据图表/访谈引言）是否前后平衡 | 前5章大量国际案例，后半无国际案例对比 |
| **句法节奏** | 长短句比例、段落密度是否与全书整体基调相符 | 某章节突然出现大量列表/条目，打破全书叙事感 |

**执行建议**：

- **单智能体串行**：建议每编完成后抽查 CX-7（与编级 CX 同步），S5 前全量执行。
- **多 Writer 并行**：合稿时 CX-7 为**必须**执行项，主编须向各 Writer 广播 `[S1] 风格档案` 并在合稿前比对各章叙事声调。
- **自动化辅助**：`scripts/quality-auditor.mjs` 可检测人称一致性（`--check-person`）和段落节奏（`--paragraph-rhythm`）；声调与例证偏好目前须人工/Auditor 智能体判断。

> **自动化**：`scripts/quality-auditor.mjs` 仍以启发式为主；CX 以 **人工 / 独立 Auditor 智能体** 为主；独立提示词模板见 [`../03-product/book-auditor-prompt.md`](../03-product/book-auditor-prompt.md)。
