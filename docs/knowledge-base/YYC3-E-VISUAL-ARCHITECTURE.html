当前AI核心层(A)各项目缺乏统一的日志、指标、追踪标准。建议引入 OpenTelemetry + Prometheus + Grafana 全链路监控，覆盖 edict 的 Redis Stream 事件、ai-agent 的 SSE 流式响应、agent-browser 的 CDP 调用链。这是实现高可用(HA)的前提条件。
影响项目: ai-agent / edict / agent-browser / claude-prompts-mcp
P0 — 立即执行
统一密钥管理与零信任安全基线
edict已有Auth Vault但各项目独立运作。建议建设统一 Secret Manager (HashiCorp Vault 或云原生 Secrets Manager)，实施 mTLS 双向认证、API Key 轮换自动化、审计日志不可篡改。agent-browser的安全策略(域白名单)应推广至所有对外接口。
影响项目: 全局基础设施层
P1 — 本季度
edict 多实例高可用部署方案
edict作为核心多Agent编排器目前为单点部署。建议采用 Kubernetes StatefulSet + Redis Sentinel 哨兵模式实现主备切换，配合 PodDisruptionBudget 保证最小可用副本数。Dashboard(:7891)需增加健康检查端点与优雅关闭逻辑。
端口规划: 后端 25791 / Dashboard 21791 (遵循哈希偏移)
P1 — 本季度
ai-agent Edge Runtime 适配与 WASM 节点支持
紧跟Edge AI趋势，将ai-agent的部分轻量节点(如文本处理、条件判断)编译为WASM模块，支持Vercel Edge Runtime / Cloudflare Workers部署。同时为agent-browser探索WASM-WASI编译路径，使其可在非Chrome环境(如Serverless函数)中运行。
技术栈: Wasmtime / JCO / Component Model

LSP-AI Bridge 桥接层建设
在语言服务层(B)与AI核心层(A)之间搭建Bridge，让rust-analyzer/sourcekit-lsp的诊断结果可直接喂给edict进行代码修复Agent调度。形成「编辑器输入 → LSP诊断 → Agent修复 → LSP验证」的闭环流水线。
