## 一、文档定位

本文档是**验收系统的执行入口**：给出可直接复制使用的验收提示词，统一所有阶段（第 1 ~ 13 阶段）的提问口径、输出结构与结论分级，避免"每个阶段各自发明一套验收口吻"。

- 想知道**有哪些阶段**：看 [闭环验收文档索引](./README.md)
- 想知道**标准条款**：看 [全局统一验收标准](./YYC3-全局统一-验收标准.md)
- 想知道**上线怎么做**：看 [上线部署-稳定运维](./YYC3-上线部署-稳定运维.md)

## 二、13 阶段流水线

```
项目起始 → ① 代码语法 → ② 功能逻辑 → ③ 测试用例 → ④ 组件测试
        → ⑤ 单元框架 → ⑥ 闭环验证 → ⑦ 数据调取 → ⑧ 安全加固
        → ⑨ 深度探索 → ⑩ 深度审核 → ⑪ 智能验收 → ⑫ 文档体系
        → ⑬ 现状审核 → 部署上线 → 稳定运维 → 复盘归档
```

阶段可**顺序执行**（推荐，前置依赖清晰），也可**按风险聚焦**（发版前一晚只跑 ①③④⑤⑥⑧）。

## 三、通用提示词模板

```text
【角色】你是 YYC³ 团队的验收审计员，遵循「五高五标五化五维」。
【范围】本次验收阶段：第 {N} 阶段（{阶段名称}）；对象：{仓库/模块/版本}。
【约束】
  1. 以代码与产物的实际状态为准，不读代码不得给结论；
  2. 不盲猜配置值、不盲测未验证命令，不确定项一律标注「待确认」；
  3. 每条结论必须给出：位置（文件:行号）、证据（命令输出/片段）、等级（P0/P1/P2）。
【动作】
  1. 读取目标文件与配置，列出关键路径；
  2. 按本阶段检查项逐条核验，记录证据；
  3. 输出《验收报告》：结论 / 通过项 / 阻断项 / 改进项 / 待确认项；
  4. 给出可执行修复方案与回归验证命令。
【输出格式】
  - 结论：✅ 通过 / ⚠️ 有条件通过 / ❌ 不通过
  - P0 阻断项（必须修复，给出最小改动方案）
  - P1 改进项（本迭代内修复）
  - P2 建议项（排期优化）
  - 待确认项（需人工确认的配置/环境）
```

## 四、分阶段提示词要点

| 阶段 | 提示词补充要求 |
| ---- | -------------- |
| 1 代码语法 | 必须贴 `tsc --noEmit`、`eslint` 的实际输出，不接受"应该没问题" |
| 2 功能逻辑 | 按用户旅程逐条走查，标注每条链路的入口与出口 |
| 3 测试用例 | 给出用例到需求的映射表，缺口单独列出 |
| 4 组件测试 | 覆盖正常/边界/异常三类，附交互与无障碍结论 |
| 5 单元框架 | 校验配置真实生效（别名、环境、include 范围） |
| 6 闭环验证 | 用一条真实业务链路端到端验证，记录追溯 ID |
| 7 数据调取 | 校验超时、重试、缓存命中和降级路径 |
| 8 安全加固 | 按 OWASP 维度逐项，密钥与 IPC 红线单独列 |
| 9 深度探索 | 高级功能不得以"实验性"跳过阻断项判定 |
| 10 深度审核 | 给出基准数据（前后对比），禁止无数据结论 |
| 11 智能验收 | AI 结论必须有人工复核路径，标注可信度 |
| 12 文档体系 | 校验 front matter、标头标尾、链接可用性 |
| 13 现状审核 | 输出改进建议的优先级与工作量估算 |

## 五、结论分级与放行规则

| 结论 | 判定条件 | 放行动作 |
| ---- | -------- | -------- |
| ✅ 通过 | 无 P0、P1 ≤ 约定阈值 | 进入下一阶段 |
| ⚠️ 有条件通过 | 无 P0、P1 超阈值但有明确修复计划 | 附条件放行，限期整改并回归 |
| ❌ 不通过 | 存在任一 P0 | 阻断合并与上线，修复后重跑本阶段 |

## 六、禁止行为

- ❌ 未读取目标代码/配置就输出验收结论
- ❌ 用"建议进一步优化"替代可执行修复项
- ❌ 把「待确认」写成「已完成」
- ❌ 只报通过项、隐藏阻断项
- ❌ 结论无证据（无命令输出、无文件行号）
