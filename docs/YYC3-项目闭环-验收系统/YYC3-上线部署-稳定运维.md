## 一、文档定位

13 个验收阶段解决的是"**质量是否达标**"，本文档解决"**达标之后如何平稳上线、上线之后如何长期稳住**"。它补齐验收系统与运维之间的缺口：

| 缺口 | 本文档补齐方式 |
| ---- | -------------- |
| 项目起始到上线的链路断点 | §二 全链路闭环链路（含起始立项门禁） |
| 验收通过 ≠ 可上线 | §三 上线门禁（退出标准 + Go/No-Go） |
| 上线动作无标准剧本 | §四 灰度与全量、§七 回滚剧本 |
| 上线后无人值守 | §六 稳定运维体系（SLO / 告警 / 值班 / 变更） |
| 上线即终点 | §八 复盘归档回到验收闭环 |

## 二、全链路闭环链路

```
① 项目起始（立项门禁）
      ↓ 需求/范围/责任人/验收标准四件套齐备
② 设计（架构总纲 + 数据边界 + 安全根）
      ↓
③ 开发（编码规范 + 标头标尾 + 类型门禁）
      ↓
④ 13 阶段闭环验收（第 1 ~ 13 阶段）
      ↓ 退出标准：无 P0、P1 有修复排期
⑤ 预发布（staging）部署 + 冒烟
      ↓
⑥ 灰度放量（分批）→ 全量上线
      ↓
⑦ 稳定运维（SLO 守护 / 告警响应 / 变更管控）
      ↓
⑧ 复盘归档 → 反哺第 1 阶段基线
```

### 2.1 起始门禁（项目起始必须落地的四件事）

| # | 交付物 | 判定 | 落位 |
| - | ------ | ---- | ---- |
| 1 | 需求与范围说明书 | 有验收标准，无"待定" | `docs/` 项目规划目录 |
| 2 | 验收标准基线 | 引用本目录 13 阶段标准 | `YYC3-全局统一-验收标准.md` |
| 3 | 责任人矩阵 | 开发 / 测试 / 运维 / 决策人各 1 | 项目 README |
| 4 | 环境与配置清单 | 环境分层 + 变量命名 + 端口分配 | `.env.example`、`docs/` 部署文档 |

> 起始门禁未齐备时，**不允许进入开发**——否则后续 13 个阶段全部失去判定基准。

## 三、上线门禁（Go / No-Go）

### 3.1 必过门禁

| 门禁 | 命令 / 证据 | 通过标准 |
| ---- | ----------- | -------- |
| 类型检查 | `npx tsc --noEmit` | 0 error |
| 单元与集成测试 | `npx vitest run` | 全绿 |
| 生产构建 | `pnpm build` | 构建成功且产物完整 |
| 依赖与密钥扫描 | `pnpm audit` + 密钥扫描 | 无高危、无明文密钥 |
| 验收结论 | 13 阶段验收报告 | 无 P0，P1 有排期 |
| 文档合规 | 标头标尾 / front matter / 链接校验 | 全部通过 |

### 3.2 Go / No-Go 判定表

| 情形 | 判定 | 动作 |
| ---- | ---- | ---- |
| 六项门禁全过 | **GO** | 进入预发布 |
| 仅文档类未达标 | **条件 GO** | 上线同步补齐，72h 内复核 |
| 存在任一 P0 或构建失败 | **NO-GO** | 阻断上线，修复后重跑 |

## 四、部署上线流程

### 4.1 环境分层

| 环境 | 用途 | 配置文件 | 密钥来源 |
| ---- | ---- | -------- | -------- |
| development | 本地开发 | `.env.development` | 本地 mock |
| staging | 预发布验证 | `.env.staging` | CI Secrets |
| production | 生产 | `.env.production` | CI Secrets（运行期注入） |

变量命名统一 `VITE_YYC3_{SYSTEM}_{KEY}`；`.env*` 必须入 `.gitignore`。

### 4.2 制品与部署形态

```bash
# 构建（合并版）
cd apps/full && pnpm build           # → dist/

# 构建镜像（多阶段：node:20-alpine → nginx:alpine）
docker build -t yyc3-ai-dev:${TAG} .
docker run -d -p 8080:80 yyc3-ai-dev:${TAG}
```

| 形态 | 适用 | 备注 |
| ---- | ---- | ---- |
| 静态托管（Netlify / Cloudflare Pages） | 纯前端产物 | 全球 CDN，零运维成本 |
| 容器（nginx 镜像） | 需要统一出口与健康检查 | 端口映射示例 `8080:80`（待确认：实际端口） |
| 桌面端（Electron 打包） | 离线与本地文件能力 | 三端同源，须过 CI `test-sync` |

### 4.3 预发布冒烟（staging 必做）

- [ ] `/health` 返回 `status: ok`
- [ ] `/health/ready` 各服务 `up`
- [ ] 登录 / 主流程 / 关键页面可访问
- [ ] 关键接口时延与生产基线量级一致
- [ ] 构建产物版本号可在页面/接口中查得

### 4.4 灰度放量

| 批次 | 比例 | 观察窗口 | 放行条件 |
| ---- | ---- | -------- | -------- |
| 第 1 批 | 内部账号 | 2h | 无 P0 报错、无错误率抬升 |
| 第 2 批 | 5% ~ 10% | 4h | 核心指标无劣化 |
| 第 3 批 | 50% | 12h | SLO 达标 |
| 全量 | 100% | 持续 | 观察 24h 后转稳定运维 |

> 无灰度能力的静态托管场景，等价做法是"先切预发布域名验证，再切主域名"，并保留**上一版本制品**以便秒级回滚。

## 五、上线检查清单（逐项打勾后放行）

### 5.1 上线前

- [ ] 变更单已审批，回滚方案已评审
- [ ] 制品已打 tag 并留存（含上一版本）
- [ ] 数据库变更已备份且有回滚脚本
- [ ] 配置与密钥已在 CI Secrets 就位
- [ ] 监控看板与告警规则已就绪
- [ ] 值班人与升级路径已确认

### 5.2 上线中

- [ ] 按批次放量，每批记录时间与指标
- [ ] 错误率、P99 时延、核心成功率三指标实时盯盘
- [ ] 异常即停：达到回滚阈值立即回滚，不做"再等等看"

### 5.3 上线后 24h

- [ ] SLO 达标（可用性、时延、错误率）
- [ ] 无新增 P0/P1 缺陷
- [ ] 日志无异常峰值，无敏感信息泄露
- [ ] 归档上线记录与验收报告，形成追溯 ID

## 六、稳定运维体系

### 6.1 SLO 基线（示例阈值，待确认后按项目实测校准）

| 指标 | 目标 | 采集方式 |
| ---- | ---- | -------- |
| 可用性 | ≥ 99.9%（月度） | 健康检查 + 拨测 |
| P99 时延 | 首屏 ≤ 2s，接口 ≤ 500ms | 前端埋点 + 网关 |
| 错误率 | ≤ 0.5% | 错误上报聚合 |
| 告警响应 | P0 ≤ 5min / P1 ≤ 15min | 值班表 |

### 6.2 监控与告警分层

| 层 | 手段 | 说明 |
| -- | ---- | ---- |
| 应用层 | `ErrorBoundary` 全覆盖 + 错误上报 | 单插件崩溃不扩散到全局 |
| 事件层 | `EventBus` 审计日志 | 关键事件可订阅、可回溯 |
| 巡检层 | 定时健康检查 | 失败自动重试与升级 |
| 业务层 | 核心链路成功率看板 | 按业务动作聚合，而非只看机器 |

### 6.3 变更管控

- 变更分级：**常规**（可灰度）/ **高风险**（涉数据、涉权限、涉密钥）/ **紧急**（线上故障修复）
- 高风险变更必须：双人评审 + 备份 + 明确回滚点 + 非高峰窗口
- 变更记录进 `CHANGELOG`，并在验收系统登记追溯 ID

### 6.4 值班与升级

| 级别 | 首次响应 | 升级对象 | 时限 |
| ---- | -------- | -------- | ---- |
| P0 线上不可用 | 5 分钟 | 技术负责人 + 决策人 | 30 分钟内给出处置方案 |
| P1 核心功能受损 | 15 分钟 | 模块负责人 | 2 小时内恢复或降级 |
| P2 局部体验受损 | 30 分钟 | 值班开发 | 当班处理 |
| P3 一般问题 | 次工作日 | 排期修复 | 迭代内 |

## 七、回滚剧本（Rollback Playbook）

```
触发条件（任一命中即回滚）
├── 错误率超过基线 3 倍且持续 5 分钟
├── 核心链路成功率 < 95%
├── P0 缺陷无法 30 分钟内修复
└── 安全事件（密钥泄露 / 越权 / 注入）

回滚动作
1. 停止放量，冻结变更
2. 切回上一版本制品（容器：切回上一 tag；静态：切回上一部署）
3. 数据层：执行已备份的回滚脚本（无脚本则禁止改数据）
4. 验证 /health 与核心链路
5. 保留现场：日志、指标快照、错误样本
6. 通报干系人，登记事故单
```

**回滚优先于修复**：线上止损优先，根因分析放到事后复盘。

## 八、复盘与归档（闭环回到验收）

| 产出 | 内容 | 归档位置 |
| ---- | ---- | -------- |
| 上线报告 | 时间线、指标曲线、放量记录 | 本项目 `docs/` |
| 事故复盘 | 根因、影响面、改进项（含责任人） | 验收系统第 13 阶段输入 |
| 基线更新 | 把新阈值写回 SLO 与验收标准 | `YYC3-全局统一-验收标准.md` |
| 知识沉淀 | FAQ / 踩坑记录 | 团队知识库 |

复盘不产出**可执行改进项**，则视为复盘未完成。

## 九、常见坑

| 坑 | 后果 | 对策 |
| -- | ---- | ---- |
| 门禁靠"目视检查" | 带病上线 | 门禁必须命令化，输出贴进报告 |
| 无上一版本制品 | 无法秒级回滚 | 每次发版留 tag 与产物 |
| 密钥写进 `.env` 提交 | 凭据泄露 | CI Secrets + `.gitignore` + 泄露即轮换 |
| 只盯机器指标 | 业务已受损却"全部健康" | 加业务成功率与关键动作埋点 |
| 上线后无人值班 | 故障发现延迟 | 值班表 + 告警升级路径 |
